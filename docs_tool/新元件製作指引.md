# 新元件製作指引

> 目的：在批次 A+B+C 重構後的架構下，提供「新增一個場景物件 / 機關」的標準步驟、範本、整合要點與避坑清單。
>
> 適用對象：未來自己（或新加入的人）增加新機關（拉桿、彈簧、計時門、移動平台、新型按鈕等）時。

## 一、共通流程（每次都套用的 11 步驟）

| 步驟 | 動作 | 跳過時機 |
|---|---|---|
| 1 | **決定類型**（無狀態/有狀態/觸發式/連續） | 不可跳 |
| 2 | **建立 `.gd`** in `godot/scripts/` | 不可跳 |
| 3 | **建立 `.tscn`** in `godot/scenes/components/` | 不可跳 |
| 4 | **加 `@tool` 與 `@export` 屬性** | 不可調尺寸/顏色時可省 |
| 5 | **實作 `_apply_*()` 視覺同步** | 純邏輯機關可省 |
| 6 | **加入 Group**（如需被 PressCounter 等掃描） | 無外部掃描需求可省 |
| 7a | **判斷是否需要 AnimationPlayer**（見 § 11） | 純地形 / 純邏輯 / 純偵測 可省 |
| 7b | **加 AnimationPlayer 子節點 + RESET + AnimationLibrary**（見 § 11） | 7a 判斷不需要時 |
| 7c | **設 callback_mode_process**（PHYSICS-critical=0、IDLE=1） | 7a 判斷不需要時 |
| 8 | **加 AudioManager 音效** | 純視覺類可省 |
| 9 | **寫 signal 與外部互動** | 完全獨立的機關可省 |
| 10 | **跑測試清單**（含 § 12 Recording 一致性測試、若有 AnimationPlayer 影響玩法） | 不可跳 |

下方「§ 五」與「§ 六」分別示範**最簡單**與**最複雜**的兩個案例。
M14a.4 後新增的 AnimationPlayer SOP / 範本 / 測試清單 / 已知坑 集中在 § 11~§ 14。

## 二、檔案配置與命名規則

### 路徑
```
godot/
├── scripts/
│   └── XxxYyy.gd           ← 腳本
└── scenes/
    └── components/
        └── XxxYyy.tscn     ← 場景
```

### 命名
- **PascalCase**：`Lever`、`Spring`、`TimedDoor`、`MovingPlatform`
- 場景與腳本同名
- `class_name` 與檔名一致

### Group（如需被外部掃描）
| Group 名 | 何時加 |
|---|---|
| `press_button` | 你做按鈕的變體（給 PressCounter 用） |
| `lever` | 你做拉桿（給未來「同步所有拉桿」用） |
| `room` | 不要自己加，Room.gd 會自動加 |
| `player_real` | 永遠不要加（保留給 Player） |
| `physical_carcass` | 永遠不要加（保留給 PhysicalCarcass） |

## 三、腳本範本（boilerplate）

直接複製、改名、依需求增刪：

```gdscript
@tool
extends Area2D                        # ← 視類型選 Area2D / StaticBody2D / Node
class_name MyMechanism

# === Signal ===
signal state_changed(value: bool)     # ← 對外廣播狀態變化（按需要）

# === 可調屬性（@export） ===
@export var size: Vector2 = Vector2(60, 30):
    set(value):
        size = value
        _apply_size()

@export var color: Color = Color(0.85, 0.6, 0.2, 1.0):
    set(value):
        color = value
        _apply_color()

# === 內部狀態 ===
var _is_active: bool = false

# === 節點引用 ===
@onready var anim: AnimationPlayer = get_node_or_null("AnimationPlayer")


# === 生命週期 ===
func _ready() -> void:
    _apply_size()
    _apply_color()
    if Engine.is_editor_hint():
        return                         # ← 編輯器內不跑運行時邏輯
    # 加 group、連 signal、註冊到 autoload 等
    body_entered.connect(_on_body_entered)


# === 視覺同步（@tool 用） ===
func _apply_size() -> void:
    var v := get_node_or_null("Visual") as Polygon2D
    var c := get_node_or_null("Collision") as CollisionShape2D
    if v == null or c == null:
        return                         # ← 防禦：setter 可能在 _ready 前被觸發
    var hx: float = size.x * 0.5
    var hy: float = size.y * 0.5
    v.polygon = PackedVector2Array([
        Vector2(-hx, -hy), Vector2(hx, -hy),
        Vector2(hx, hy), Vector2(-hx, hy)
    ])
    if c.shape is RectangleShape2D:
        (c.shape as RectangleShape2D).size = size
    else:
        var rect := RectangleShape2D.new()
        rect.size = size
        c.shape = rect


func _apply_color() -> void:
    var v := get_node_or_null("Visual") as Polygon2D
    if v != null:
        v.color = color


# === 行為邏輯 ===
func _on_body_entered(body: Node2D) -> void:
    # 處理觸發
    pass
```

### 範本的關鍵規則
1. `@tool` 必加 — 編輯器內預覽
2. `_apply_*()` 一定要 `get_node_or_null()` 防禦 — setter 可能在 `_ready` 前就觸發
3. `_ready()` 開頭呼叫 `_apply_*()`、然後 `if Engine.is_editor_hint(): return` — 確保編輯器內看得到、不跑運行時邏輯
4. 視覺與碰撞同步：改 `size` 自動更新 Polygon 與 CollisionShape

## 四、場景範本（boilerplate）

```
[gd_scene load_steps=3 format=3]

[ext_resource type="Script" path="res://scripts/MyMechanism.gd" id="1_mech"]

[sub_resource type="RectangleShape2D" id="RectangleShape2D_mech"]
size = Vector2(60, 30)

[node name="MyMechanism" type="Area2D"]
collision_layer = 0
collision_mask = 3
script = ExtResource("1_mech")

[node name="Visual" type="Polygon2D" parent="."]
color = Color(0.85, 0.6, 0.2, 1)
polygon = PackedVector2Array(-30, -15, 30, -15, 30, 15, -30, 15)

[node name="Collision" type="CollisionShape2D" parent="."]
shape = SubResource("RectangleShape2D_mech")
```

### 場景結構規則
- 根節點命名與 `class_name` 一致
- 永遠有 `Visual` (Polygon2D) 和 `Collision` (CollisionShape2D) 子節點
- 預設 collision_layer/mask 跟同類元件一致：
  - 偵測類（Button、Trigger、Lever）：layer=0, mask=3
  - 實體類（Door、Platform）：layer=1, mask=0（或預設）
  - 危險類（HazardZone、Spike）：layer=0, mask=3

## 五、完整範例：彈簧 Spring（無狀態觸發類）

> 最單純的機關。展示「Area2D 觸發 + 自動回應 + 不需 Recording 修改」的完整流程。

### 5.1 設計目標

- 玩家/分身落上去 → 強制向上彈起
- 視覺有壓縮回彈動畫
- 不需互動鍵、不需 Recording 修改
- Inspector 可調 `bounce_velocity`

### 5.2 `godot/scripts/Spring.gd`

```gdscript
@tool
extends Area2D
class_name Spring

# 彈簧：玩家/分身落上時強制向上彈起、與 Recording 系統天然相容
# 玩家行為由「物理引擎 + apply_bounce」共同決定，但分身重現時仍然走相同的物理模擬，
# 所以不需要在 Recording 內存任何彈簧相關資料。

@export var bounce_velocity: float = -800.0  # 負值 = 向上
@export var size: Vector2 = Vector2(60, 20):
    set(value):
        size = value
        _apply_size()
@export var color: Color = Color(0.3, 0.7, 1.0, 1.0):
    set(value):
        color = value
        _apply_color()

@onready var anim: AnimationPlayer = get_node_or_null("AnimationPlayer")


func _ready() -> void:
    _apply_size()
    _apply_color()
    if Engine.is_editor_hint():
        return
    body_entered.connect(_on_body_entered)


func _apply_size() -> void:
    var v := get_node_or_null("Visual") as Polygon2D
    var c := get_node_or_null("Collision") as CollisionShape2D
    if v == null or c == null:
        return
    var hx: float = size.x * 0.5
    var hy: float = size.y * 0.5
    v.polygon = PackedVector2Array([
        Vector2(-hx, -hy), Vector2(hx, -hy),
        Vector2(hx, hy), Vector2(-hx, hy)
    ])
    if c.shape is RectangleShape2D:
        (c.shape as RectangleShape2D).size = size
    else:
        var rect := RectangleShape2D.new()
        rect.size = size
        c.shape = rect


func _apply_color() -> void:
    var v := get_node_or_null("Visual") as Polygon2D
    if v != null:
        v.color = color


func _on_body_entered(body: Node2D) -> void:
    # 只對有 apply_bounce 的物體有效（Player 與 Clone）；殘骸無 method 不彈
    if not body.has_method("apply_bounce"):
        return
    body.apply_bounce(bounce_velocity)
    AudioManager.play_sfx_at("spring_bounce", global_position)
    if anim != null:
        anim.play("compress")
```

### 5.3 `godot/scenes/components/Spring.tscn`

```

[node name="Visual" type="Polygon2D" parent="."]

[node name="Collision" type="CollisionShape2D" parent="."]

```

### 5.4 整合：Player.gd 加 apply_bounce

[Player.gd](../godot/scripts/Player.gd) 結尾加：

```gdscript
# 由 Spring 等機關呼叫，強制設定垂直速度（向上彈）
# 重置 coyote/jump_buffer 避免「彈起後立刻又能跳」造成不可預期行為
func apply_bounce(vy: float) -> void:
    velocity.y = vy
    coyote_timer = 0.0
    jump_buffer_timer = 0.0
```

> Clone 透過繼承 Player 自動有此方法，無需另寫。

### 5.5 加入動畫（可選但推薦）

在 Spring.tscn 加 AnimationPlayer 子節點，建一個 `compress` 動畫：

| 時間 | 屬性 | 值 |
|---|---|---|
| 0.0s | `Visual:scale` | (1, 1) |
| 0.05s | `Visual:scale` | (1.2, 0.4) |
| 0.2s | `Visual:scale` | (1, 1) |

`anim.play("compress")` 在 `_on_body_entered` 內呼叫（已在腳本內）。

### 5.6 在房間中使用

在 `demo_roomN.tscn` 內：
1. 把 `components/Spring.tscn` 拖進場景
2. 設定 position
3. （可選）改 Inspector 的 `bounce_velocity`、`size`、`color`
4. 完成

### 5.7 為何不需動 Recording

關鍵理解：

> Recording 系統只記錄**輸入**（left/right/jump），不記錄狀態或速度。
> 分身重現時跑同一份 `_apply_movement()` 物理計算，
> 同樣的輸入序列 + 同樣的世界 = 同樣的軌跡（包括踩到彈簧那一刻被彈起）。

所以**只要新機關不引入新輸入鍵，Recording 永遠相容**。

## 六、進階範例：拉桿 Lever（有狀態 + 互動鍵）

> 展示需要修改 Recording 系統的高複雜度案例。先看「兩種設計選項對比」決定走哪條。

### 6.1 設計目標

- 玩家走到拉桿前按 E 切換狀態（toggle）
- 切換時 emit `state_changed` signal、可連到 Door 開合
- 視覺隨狀態變色 / 翻轉
- 玩家可重複切換、分身重現時必須**重播相同切換**

### 6.2 兩種設計選項對比

| 選項 | 觸發方式 | Recording 改動 | 設計感 |
|---|---|---|---|
| **A. 跨壓式** | 玩家從上方壓過拉桿（Area2D body_entered）| ❌ 無需改動 | 平台跳躍味 |
| **B. E 鍵互動式** | 玩家走到拉桿前按 E | ✓ 需擴 input_frames | RPG/解謎味 |

> 餘響的詩意基調建議走 **A 跨壓式**。E 鍵改動成本高、且新增按鍵會讓玩家認知負擔上升。

### 6.3 簡單版：跨壓觸發（無 Recording 改動）— 建議走這條

```gdscript
@tool
extends Area2D
class_name Lever

signal state_changed(is_on: bool)

@export var initial_state: bool = false
@export var color_on: Color = Color(0.3, 0.85, 0.3, 1.0)
@export var color_off: Color = Color(0.5, 0.5, 0.55, 1.0)

var is_on: bool = false

@onready var anim: AnimationPlayer = get_node_or_null("AnimationPlayer")


func _ready() -> void:
    is_on = initial_state
    _apply_visual()
    if Engine.is_editor_hint():
        return
    add_to_group("lever")
    body_entered.connect(_on_body_entered)


func _on_body_entered(body: Node2D) -> void:
    # 接受 Player 與 Clone（CharacterBody2D），不接受殘骸
    if not (body is CharacterBody2D):
        return
    _toggle()


func _toggle() -> void:
    is_on = not is_on
    state_changed.emit(is_on)
    AudioManager.play_sfx_at("lever_toggle", global_position)
    if anim != null:
        anim.play("flip_on" if is_on else "flip_off")
    else:
        _apply_visual()


func _apply_visual() -> void:
    var v := get_node_or_null("Visual") as Polygon2D
    if v != null:
        v.color = color_on if is_on else color_off
```

> 玩家走過 → toggle；分身重現時必然走同樣路徑 → 也 toggle 同樣次數 → **狀態一致**。Recording 完全不必改。

### 6.4 完整版：E 鍵互動式（需 Recording 擴展）

如果你堅持要 E 鍵互動，需要做 **4 處系統改動**：

#### Step 1：擴 Input Map
Project Settings → Input Map 加 `interact` action（綁 E 鍵）。

#### Step 2：擴 Recording.gd

```gdscript
class_name Recording
extends Resource

@export var spawn_position: Vector2 = Vector2.ZERO
@export var input_frames: Array[Dictionary] = []  
# 舊：[{left, right, jump}]
# 新：[{left, right, jump, interact}]

# 其他不變
```

#### Step 3：擴 Player.gd

```gdscript
var input_interact := false
var input_interact_prev := false

func _read_inputs() -> void:
    input_left = Input.is_action_pressed("move_left")
    input_right = Input.is_action_pressed("move_right")
    input_jump = Input.is_action_pressed("jump")
    input_interact = Input.is_action_pressed("interact")

func _record_frame_if_needed() -> void:
    if RecordingManager.is_recording():
        RecordingManager.add_frame(input_left, input_right, input_jump, input_interact)
```

#### Step 4：擴 RecordingManager.gd

```gdscript
func add_frame(left: bool, right: bool, jump: bool, interact: bool) -> void:
    current_recording.input_frames.append({
        "left": left, "right": right, "jump": jump, "interact": interact
    })
```

#### Step 5：擴 Clone.gd 從 Recording 讀 interact

```gdscript
func _read_inputs() -> void:
    if current_frame >= recording.input_frames.size():
        # 錄製結束
        return
    var frame: Dictionary = recording.input_frames[current_frame]
    input_left = frame.get("left", false)
    input_right = frame.get("right", false)
    input_jump = frame.get("jump", false)
    input_interact = frame.get("interact", false)
    current_frame += 1
```

#### Step 6：Lever 改用 _input

```gdscript
var _player_in_range: bool = false

func _input(event: InputEvent) -> void:
    if Engine.is_editor_hint(): return
    if not _player_in_range: return
    if event.is_action_pressed("interact"):
        _toggle()

func _on_body_entered(body):
    if body.is_in_group("player_real"):
        _player_in_range = true

func _on_body_exited(body):
    if body.is_in_group("player_real"):
        _player_in_range = false
```

> ⚠️ 注意：分身重現時不會發 InputEvent；要改寫成「Clone 每幀檢查自己的 input_interact，配合範圍偵測呼叫 _toggle」。這部分牽動很多現有邏輯，**強烈建議走 6.3 簡單版**。

### 6.5 連結到 Door

在 `demo_roomN.tscn` 內：
- 加一個 Lever 實例
- 加一個 Door 實例

在房間的腳本裡（或 World.gd 內）：


新機關歸類到哪個範本：

| **單向門** | Door 變體 | ✓ 自動 | 用 one_way_collision |
| **直線移動平台** | 新元件 + AnimationPlayer 路徑 | ✓ 自動 | Clone 要會跟著平台 |
| **觸發式電梯** | 新元件 | ✓ 自動 | 配合按鈕 signal 啟動 |
| **崩落平台** | 新元件 | △ 視設計 | 是否「重現時也崩」是設計選擇 |
| **輸送帶** | 新元件 | △ 影響玩家速度 | 建議避開（影響軌跡可預測性） |

| **加速墊** | Spring 變體 | ✓ 自動 | 同 Spring，套水平向 |
| **梯子** | 新元件 | ✗ 改 Player 移動 | 改 Player 動作會影響 Recording |

> 表內標 ✗ 的機關都需要慎重評估「值不值得」。優先做標 ✓ 的。

## 八、與系統整合

### 8.1 Recording 一致性（最重要）

**核心原則**：
> 同樣的輸入序列 + 同樣的世界 = 同樣的軌跡

**做到這件事的紀律**：
1. 機關行為只能用 `_physics_process`（不要用 `_process`、`Timer.timeout`、`await get_tree().create_timer`）
2. 不要用隨機數；若必要，用固定 seed
3. 不要引入新輸入鍵（除非接受 6.4 的擴展成本）
4. 不要用 RigidBody2D 做受玩家影響的物件
5. 機關狀態改變必須**確定性**：「Player 在 frame N 觸發」每次都應該在 frame N

**驗證方法**：
- 錄一段機關互動
- 重現 3 次
- 觀察分身軌跡與機關狀態是否每次都一致

### 8.2 Audio 距離衰減

**永遠用** [`AudioManager.play_sfx_at(name, position)`](../godot/scripts/AudioManager.gd) — 不要直接 `AudioStreamPlayer.play()`。

理由：
- 自動套距離衰減（離鏡頭遠的機關音量減小）
- 自動掛 SFX bus（玩家可在設定調 SFX 音量）
- 統一管理 SFX 名稱（避免硬編碼路徑）

需新增音效時：
1. 把 `.wav` / `.ogg` 放 `audio/sfx/`
2. 在 [AudioManager.gd](../godot/scripts/AudioManager.gd) 註冊（找已有的 sfx 列表）
3. 機關內呼叫 `AudioManager.play_sfx_at("your_sfx_name", global_position)`

### 8.3 AnimationPlayer 整合

**在元件內加 AnimationPlayer 子節點**，不要在 autoload 跑動畫：

```
MyMechanism (Area2D)
├── Visual (Polygon2D)
├── Collision (CollisionShape2D)
└── AnimationPlayer
     ├── RESET（強制建議、Godot 慣例）
     ├── compress (動畫)
     ├── flip_on
     └── flip_off
```

腳本內：

```gdscript
@onready var anim: AnimationPlayer = get_node_or_null("AnimationPlayer")

func _ready() -> void:
    if Engine.is_editor_hint(): return
    # M14a.4：影響玩法（碰撞 / 位移 / 可踩可穿）的動畫必須走 PHYSICS callback、保 Recording deterministic
    if anim != null:
        anim.callback_mode_process = AnimationMixer.ANIMATION_CALLBACK_MODE_PROCESS_PHYSICS

func trigger():
    if anim != null:
        anim.play("compress")
```

> 用 `get_node_or_null` 而非 `$AnimationPlayer` —— 允許動畫元件先不加，後期再補。
> 詳細 SOP（含命名規範 / RESET 軌 / callback_mode 選擇 / Door 範本）見 § 11、Recording 驗證見 § 12、避坑見 § 13。

### 8.4 Custom Resource 配置

**只把「設計師會頻繁調整」的數值做成 .tres**。其他保持 `@export var`。

範例：給 Spring 做配置卡

```gdscript
# scripts/SpringConfig.gd
class_name SpringConfig
extends Resource

@export var bounce_velocity: float = -800.0
@export var sfx_name: String = "spring_bounce"
@export var color: Color = Color(0.3, 0.7, 1.0)
```

Spring.gd 改：

```gdscript
@export var config: SpringConfig

func _on_body_entered(body):
    if not body.has_method("apply_bounce"): return
    body.apply_bounce(config.bounce_velocity)
    AudioManager.play_sfx_at(config.sfx_name, global_position)
```

之後可建多個 Resource：
- `data/spring_normal.tres` (-800)
- `data/spring_super.tres` (-1500)
- `data/spring_weak.tres` (-400)

每個 Spring 實例 inspector 拖一個 .tres 進去就用該套設定。

### 8.5 Group 掃描（給 PressCounter 等用）

如果你做的機關**需要被外部掃描**（如做新型按鈕、要被 PressCounter 計數），加 group：

```gdscript
func _ready():
    # ...
    if Engine.is_editor_hint(): return
    add_to_group("press_button")  # 或自訂的 group
```

外部用 `get_tree().get_nodes_in_group("press_button")` 找出所有按鈕。

> 只在「會被多個地方掃」的情境用 group。普通的 1-對-1 連線用 NodePath 即可。

## 九、常見地雷

### 地雷 1：忘記 `_apply_*()` 的防禦
**症狀**：場景一開啟報錯 "Cannot access null"，或編輯器內某些屬性顯示異常。

**原因**：`@export var size:set:` setter 在 `_ready` 之前就會被呼叫（場景載入時），此時 `$Visual` 還沒解析。

**正確寫法**：
```gdscript
func _apply_size():
    var v := get_node_or_null("Visual") as Polygon2D  # ← null check
    if v == null: return
    # ...
```

### 地雷 2：`@tool` 腳本在編輯器內跑了不該跑的程式
**症狀**：開啟場景後 Godot console 噴 AudioManager 找不到、PlayerController 沒註冊等錯誤。

**原因**：`@tool` 腳本的 `_ready()` 在編輯器也跑。autoload 在編輯器內**不存在**。

**正確寫法**：
```gdscript
func _ready():
    _apply_size()                       # 視覺更新可在編輯器跑
    if Engine.is_editor_hint(): return  # 之後的不跑
    add_to_group("press_button")
    body_entered.connect(_on_body_entered)
    AudioManager.something()             # 這個只在運行時 OK
```

### 地雷 3：碰撞形狀「shared」污染
**症狀**：改一個元件實例的尺寸，所有其他實例也跟著變。

**原因**：`@export` 的 RectangleShape2D 是 shared resource。多個實例共用同一個 shape。

**正確寫法**：在 `_apply_size()` 內 `new()` 一個新 shape：
```gdscript
if c.shape is RectangleShape2D:
    (c.shape as RectangleShape2D).size = size  # 同實例 OK
else:
    var rect := RectangleShape2D.new()
    rect.size = size
    c.shape = rect
```

> 為啥還是這樣寫？因為 .tscn 內 sub_resource 是 unique per scene file，instance 時 Godot 會複製。但「inspector 內貼上的 shape」可能是 shared。雙保險寫法。

### 地雷 4：Clone 不繼承新方法
**症狀**：你給 Player 加了 `apply_bounce`，Player 會彈但 Clone 不會。

**原因**：Clone 可能 override 了 `_ready` 或某些方法但沒呼叫 `super`。

**檢查**：[Clone.gd](../godot/scripts/Clone.gd) 看是否乾淨繼承 Player.gd。新增的 method 應自動繼承到 Clone（GDScript 預設行為）。

### 地雷 5：機關 emit signal 但 Door 沒接到
**症狀**：拉桿切換、視覺變了但門不開。

**原因**：你在 `demo_roomN.tscn` 內擺了 Lever 與 Door，但**沒有寫連線程式**。

**正確流程**：
- 連線寫在「擁有兩端的父節點」
- 對 demo_room5（假設新房間），可加自己的 .gd：

```gdscript
# scripts/demo_room5.gd
extends Node2D

func _ready():
    $Lever.state_changed.connect($Door.set_target)
```

或寫在 World.gd（如果你想集中管理）。

### 地雷 6：把行為寫進場景而非腳本
**症狀**：複製場景時行為跟著走，但改一處所有實例都變，無法做變體。

**原因**：把 `is_inverted = true` 之類的「資料」用 inspector 設在元件實例上**很好**；但把「行為差異」（不同 emit 邏輯）寫死在元件內**不好**。

**規則**：
- 同一行為 + 不同參數 → @export var、@export Resource
- 不同行為 → 不同 class（繼承或獨立）

### 地雷 7：忘記在 demo_roomN.tscn 內加房間 .gd 後遺忘 connect
**症狀**：機關動作正常但跨機關互動沒效。

**原因**：批次 C 後，房間是獨立 .tscn 但沒 .gd 腳本。要加機關互動需要：
- 在房間 .gd 內 connect
- 或在 World.gd 用 `$demo_room5/Lever` 路徑連線

優先選**房間自己的 .gd**（封閉性更好）。

## 十一、AnimationPlayer 套用 SOP（M14a.4 後 / Door 範本）

> M14a.4 已驗證 Door 在 PHYSICS callback 下 Recording deterministic 一致。本節是「**新元件需要動畫時**」的固定 SOP、抄 Door 範本即可。

### 11.1 何時加 AnimationPlayer

依 [動畫狀態 Mapping Spec.md § 4.8](../docs/動畫狀態%20Mapping%20Spec.md) 反推「**不加**」的清單：

| 元件類型 | 是否加 AnimationPlayer |
|---|---|
| 純地形（Platform）| ✗ |
| 純致死區（HazardZone）| ✗ |
| 純偵測（TriggerZone）| ✗ |
| 純邏輯抽象（LogicGate / PressCounter / CloneSpawner）| ✗ |
| 殘骸落地後靜態（PhysicalCarcass）| ✗ |
| 任何「玩家或分身會互動且有視覺/碰撞變化」的元件 | ✓ |
| 任何 Tween 既有元件（PressButton / Checkpoint / Sign / LightPoint 等）| ✓（M14a 全面遷移）|

> 例外：UI 既有 Tween（HUD / TitleScreen / PauseMenu / EndingScreen / MapOverlay）**不**遷移、見 [Mapping Spec § 五](../docs/動畫狀態%20Mapping%20Spec.md)。

### 11.2 場景樹位置

AnimationPlayer 與 Visual / Collision 同層、放在元件根節點底下：

```
ComponentName (Root: Area2D / StaticBody2D / AnimatableBody2D)
├── Visual (Polygon2D / Sprite2D / Node2D)
├── Collision (CollisionShape2D)
├── DetectArea (Area2D, 若有)
└── AnimationPlayer            ← 與 Visual / Collision 同層
    └── (含 AnimationLibrary "")
        ├── RESET              ← 強制建議
        ├── idle               ← 靜態預設（可選）
        └── <state_anim_*>     ← 對應 Mapping Spec 的動畫名
```

### 11.3 AnimationLibrary 結構（含 RESET 軌）

- 每個 AnimationPlayer **必有 `RESET`** 軌、Godot 慣例（用來拍下初始值、編輯器內可一鍵還原）
- RESET 的 path 至少指向 `Visual:modulate`（最低限度）、若元件還有額外屬性會在動畫中變動、RESET 都應拍下對應初始值
- 動畫名**不加元件前綴**（用 `open` 不用 `door_open`、因為已在 Door 內部）
- AnimationLibrary key 用空字串 `""`（預設 library、播動畫時直接 `anim.play("open")` 不必加 library 前綴）

範例（取自 Door.tscn）：

```
[sub_resource type="Animation" id="Animation_RESET"]
length = 0.001
tracks/0/type = "value"
tracks/0/path = NodePath("Visual:modulate")
tracks/0/keys = {
"times": PackedFloat32Array(0),
"values": [Color(1, 1, 1, 1)]
...
}

[sub_resource type="AnimationLibrary" id="AnimationLibrary_default"]
_data = {
"RESET": SubResource("Animation_RESET"),
"close": SubResource("Animation_close"),
"closed": SubResource("Animation_closed"),
"open": SubResource("Animation_open")
}

[node name="AnimationPlayer" type="AnimationPlayer" parent="."]
callback_mode_process = 0
libraries = {
"": SubResource("AnimationLibrary_default")
}
```

### 11.4 callback_mode_process 設定

| 模式 | .tscn 整數值 | Inspector 顯示 | 何時用 |
|---|---|---|---|
| **PHYSICS** | `callback_mode_process = 0` | "Physics" | **PHYSICS-critical**：動畫直接影響玩法（碰撞 / 位移 / 可踩可穿）、Recording 必須一致 |
| **IDLE** | `callback_mode_process = 1` | "Idle" | 純視覺：UI / 純 modulate / 純背景效果 |
| **MANUAL** | `callback_mode_process = 2` | "Manual" | 罕用、需腳本手動推進 tick |

> 預設值是 IDLE（1）—— 對影響玩法的元件**必改為 0**、否則 Recording 重現會飄。

腳本內也建議加一道保險（即使 .tscn 裡已設、也再寫一次）：

```gdscript
@onready var anim: AnimationPlayer = $AnimationPlayer

func _ready() -> void:
    if Engine.is_editor_hint(): return
    if anim != null:
        anim.callback_mode_process = AnimationMixer.ANIMATION_CALLBACK_MODE_PROCESS_PHYSICS
```

### 11.5 用法：anim.play() 取代 _physics_process 手刻

**舊寫法（_physics_process 手刻 lerp）**：

```gdscript
func _physics_process(delta):
    progress += delta / OPEN_TIME
    visual.scale.y = lerp(1.0, 0.001, progress)
    if progress >= 1.0:
        collision.disabled = true   # ⚠ physics frame 中改 disabled、容易穿模
```

**新寫法（AnimationPlayer + method track）**：

```gdscript
func set_target(open: bool) -> void:
    if anim == null: return
    if open:
        anim.play("open")
    else:
        anim.play("close")
```

碰撞切換交給動畫的 method track 呼叫 `_set_collision_disabled(value)`、用 `set_deferred` 避開 physics frame。詳見 § 12。

## 十二、AnimationPlayer 套用範本（M14a.4 Door 範例）

> 把 Door 的關鍵段落抄一份在這裡、未來新元件直接複製改名即可。

### 12.1 set_target() — 反轉處理（mid-animation 切方向）

```gdscript
const OPEN_TIME := 0.6  # 與 .tscn 的 "open" / "close" 動畫 length 一致

# 由按鈕的 pressed_changed signal 呼叫
# 用 anim.play() 取代 _physics_process 手刻、collision.disabled 由動畫 method track 切換
# 反轉處理：若動畫進行中切方向、用 seek 從鏡像位置繼續、保視覺連續
func set_target(open: bool) -> void:
    if open == should_open:
        return  # 狀態未變、不重觸發
    if open:
        AudioManager.play_sfx_at("door_open", global_position)
    should_open = open
    if anim == null:
        return
    # 捕捉前一動畫位置（用於鏡像反轉）
    var prev_pos := anim.current_animation_position if anim.is_playing() else 0.0
    if open:
        anim.play("open")
    else:
        anim.play("close")
    # 鏡像反轉：從上一動畫進度的鏡像位置繼續播放、避免視覺跳變
    if prev_pos > 0 and prev_pos < OPEN_TIME:
        anim.seek(OPEN_TIME - prev_pos, true)
```

> 重點：**不要重播**（會看到視覺跳回起點再走）、用 `anim.seek(OPEN_TIME - prev_pos, true)` 從鏡像位置繼續、玩家看起來就是「順順反向」。

### 12.2 _set_collision_disabled() — 用 set_deferred 避免 physics frame 問題

```gdscript
# 由 .tscn 內 AnimationPlayer 的 method track 呼叫
# 用 set_deferred 避免在 physics frame 中改 disabled（broadphase 同步問題）
# "open" 動畫於 t=OPEN_TIME 呼叫 _set_collision_disabled(true)
# "close" 動畫於 t=0.0 呼叫 _set_collision_disabled(false)
func _set_collision_disabled(value: bool) -> void:
    if collision != null:
        collision.set_deferred("disabled", value)
```

> 若直接讓 method track 寫成 `Collision:disabled` value track、Godot 在 physics frame 中改 disabled 容易讓 broadphase 來不及同步、導致玩家穿模一兩格。用 method track + set_deferred 是 M14a.4 已驗證可用的解。

### 12.3 method track 在 .tscn 中的格式（給未來手寫 .tscn 抄）

```
[sub_resource type="Animation" id="Animation_open"]
length = 0.6
tracks/0/type = "value"
tracks/0/path = NodePath("Visual:scale:y")
tracks/0/interp = 1
tracks/0/keys = {
"times": PackedFloat32Array(0, 0.6),
"transitions": PackedFloat32Array(1, 1),
"update": 0,
"values": [1.0, 0.001]
}
tracks/1/type = "method"
tracks/1/path = NodePath(".")
tracks/1/keys = {
"times": PackedFloat32Array(0.6),
"transitions": PackedFloat32Array(1),
"values": [{
"args": [true],
"method": &"_set_collision_disabled"
}]
}
```

> 重點欄位：
> - `tracks/N/type = "method"`
> - `tracks/N/path = NodePath(".")`（指向元件自己 = 該節點掛的 script 上的 method）
> - `keys.values` 是 Array of Dictionary、每個 dict 含 `args`（陣列）和 `method`（StringName、用 `&"name"` 字面值）
> - 切記 `times` 要對齊到「視覺已完成切換」的時間點（open 是動畫**結尾** t=0.6、close 是動畫**開頭** t=0.0）

## 十三、Recording 一致性測試清單（M14a.4 已驗證）

> M14a.4 用這份清單驗證 Door、通過後才開放給 TriggeredPlatform / CrumblingPlatform。
> 未來任何「PHYSICS-critical 動畫」元件套 AnimationPlayer 後、跑一遍即可。

### 13.1 基本功能驗證（5 步）

- [ ] 編輯器開啟元件 .tscn 沒報錯、動畫可在 AnimationPlayer 面板手動播放
- [ ] 跑遊戲、按鈕按下 → 動畫正向播放、視覺正確
- [ ] 按鈕鬆開 → 動畫反向播放、視覺正確
- [ ] 動畫結束時 collision 切換正確（門開關、平台落 / 升、可踩 / 不可踩）
- [ ] Mid-animation 反轉（動畫播一半就切回去）→ 視覺不跳變、`anim.seek` 鏡像位置生效

### 13.2 Recording 一致性驗證（7 步）

1. 進入含此元件的房間、開始錄製
2. 玩一段含此元件互動的流程（觸發開、觸發關、跨機關、踩平台、被門擋等）
3. 結束錄製、產生分身
4. **第 1 次重現**：觀察分身軌跡與機關狀態切換時刻
5. 重新整理場景、再錄一次相同流程
6. **第 2 次重現**：軌跡與機關切換時刻**必須與第 1 次完全一致**
7. **第 3 次重現**：再驗證一次（共 3 次）

### 13.3 通過 / 失敗判準

| 判準 | 通過 | 失敗 |
|---|---|---|
| 分身軌跡 | 3 次重現完全重疊 | 任一次有偏移 |
| 機關狀態切換時刻 | 3 次相同 frame 切換 | 切換時刻飄移 |
| 玩家是否被擋 / 穿過 | 3 次結果一致 | 有時穿、有時擋 |
| 音效播放時刻 | 3 次相同 frame 播 | 音效時間飄 |

### 13.4 失敗時的回退

按 [Mapping Spec § 六](../docs/動畫狀態%20Mapping%20Spec.md) 的 M14a.4 風險矩陣、若**致命級**（Door / TriggeredPlatform / CrumblingPlatform）失敗：

```bash
# 回退到上一個已通過的 commit（m14a.4 之前 _physics_process 手刻版本）
git log --oneline                 # 找回退目標
git checkout <commit_hash> -- godot/scripts/<元件>.gd godot/scenes/components/<元件>.tscn
# 確認回退後再次跑 13.2 驗證
```

> 若**中-低級**失敗（PressButton / Lever / Checkpoint）、視覺退化可接受、可保留 AnimationPlayer 改為 IDLE callback 走純視覺路徑、把功能部分仍走原 signal。

### 13.5 未來新元件套 AnimationPlayer 時

跑一遍 § 13.1 + § 13.2 + 對 § 13.3 確認、即可放行。
若元件不影響玩法（callback_mode = IDLE）、可省略 § 13.2、只跑 § 13.1。

## 十四、常見地雷（M14a.4 補強）

接 § 九的 7 個地雷後再加：

### 地雷 8：Godot 4.3+ enum 改名

**症狀**：`AnimationPlayer.ANIMATION_PROCESS_PHYSICS` 報錯找不到、或編譯期間 missing identifier。

**原因**：Godot 4.3+ 把 `callback_mode_process` 的 enum 從 `AnimationPlayer` 搬到父類 `AnimationMixer`、舊符號移除。

**正確寫法**：

```gdscript
# 舊（Godot 4.0~4.2）：
anim.callback_mode_process = AnimationPlayer.ANIMATION_PROCESS_PHYSICS  # ✗ 4.3+ 不可用

# 新（Godot 4.3+）：
anim.callback_mode_process = AnimationMixer.ANIMATION_CALLBACK_MODE_PROCESS_PHYSICS  # ✓
```

> 本專案用 Godot 4.x（4.3+）、必用新名。

### 地雷 9：.tscn 整數值容易記反

**症狀**：開啟 .tscn、Inspector 顯示 callback_mode = "Idle"、但你以為設了 PHYSICS、Recording 重現飄。

**正確對應**（M14a.4 反覆踩過）：

| .tscn 整數值 | Inspector 顯示 | 含義 |
|---|---|---|
| `callback_mode_process = 0` | "Physics" | PHYSICS（玩法相關必用） |
| `callback_mode_process = 1` | "Idle" | IDLE（純視覺） |
| `callback_mode_process = 2` | "Manual" | MANUAL |

> 直覺上「0 = 預設 = Idle」**錯**、實際 0 才是 PHYSICS。手寫 .tscn 時請對著上表確認。

### 地雷 10：AnimationPlayer 改 collision.disabled 必須走 method track + set_deferred

**症狀**：門關上瞬間玩家穿過去、或門開啟瞬間玩家被卡 1~2 frame、不一致地發生。

**原因**：AnimationPlayer 在 physics frame 中直接改 `Collision:disabled`（用 value track）會讓 broadphase 來不及同步。

**正確寫法**：
1. 動畫加 method track、path 指向元件根 `NodePath(".")`
2. 動畫呼叫元件腳本的 `_set_collision_disabled(value)` method
3. method 內用 `collision.set_deferred("disabled", value)`、不要直接 `collision.disabled = value`

```gdscript
func _set_collision_disabled(value: bool) -> void:
    if collision != null:
        collision.set_deferred("disabled", value)
```

> M14a.4 在 Door 上驗證 3 次重現完全一致。

### 地雷 11：mid-animation 反轉用 seek、不要重播

**症狀**：玩家連續快速切換按鈕、門視覺一直跳回起點再開、感覺很頓。

**正確寫法**：抓前一動畫的 `current_animation_position`、播反向動畫後用 `anim.seek(OPEN_TIME - prev_pos, true)` 從鏡像位置繼續：

```gdscript
var prev_pos := anim.current_animation_position if anim.is_playing() else 0.0
anim.play("close" if not open else "open")
if prev_pos > 0 and prev_pos < OPEN_TIME:
    anim.seek(OPEN_TIME - prev_pos, true)
```

> 第二參數 `true` = 強制 update（不等下一個 process tick）、保 Recording 一致。

### 地雷 12：既有 Tween 元件的取捨（不是全部都遷移）

**症狀**：有人興沖沖把 HUD / TitleScreen 的 Tween 也搬到 AnimationPlayer、結果 PR 暴增。

**規則**（[Mapping Spec § 五](../docs/動畫狀態%20Mapping%20Spec.md)）：

| 類別 | 是否遷移 | 為何 |
|---|---|---|
| Door / TriggeredPlatform / CrumblingPlatform | ✓ 必遷 | PHYSICS-critical、玩法相關 |
| PressButton / Checkpoint / Lever / Spring | ✓ 遷 | 玩法相關（Recording 路徑） |
| Sign / LightPoint / Teleporter | ✓ 遷（IDLE 即可） | 命名統一、未來可換 |
| HUD / TitleScreen / PauseMenu / EndingScreen / MapOverlay UI Tween | ✗ 不遷 | 純 UI、Recording 無關、節省工時 |
| CarcassTrace 60s 顏色漸變 | ✗ M14a 不動 | 既有邏輯穩定、M14b 視需要再評估 |
