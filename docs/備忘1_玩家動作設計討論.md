## 二、R 鍵重錄該槽位的必要性

### 現況
玩家**站在亮光點上**按 R → 進入「重錄此槽位」模式、覆寫該槽位（不走 FIFO）。  
R 鍵優先序：傳送門 > 重錄該槽位 > 結束錄製 > 新錄製。

### 保留的論點

| 角度 | 說明 |
|---|---|
| **UX 效率** | 1 步操作（站光點 + R）vs Q 刪除 → 走別處 → R 新錄 = 3 步 |
| **位置保留** | 重錄保留該槽位的「時序位置」、不會被 FIFO 推走 |
| **詩意主題** | 站在過去的位置上「重新做一次」= 餘響「修正過去」核心隱喻具象化 |
| **熟練玩家友善** | speedrun / 高難度試錯時極大時間節省 |

### 拿掉的論點

| 角度 | 說明 |
|---|---|
| **概念複雜** | R 鍵 4 種行為對新手難理解 |
| **誤觸風險** | 想新錄但站太靠近光點 → 蓋掉原本想保留的槽位 |
| **可被替代** | Q + R 兩鍵組合可達同樣結果（少 1 個概念）|

### 結論

**保留 + 加 HUD 上下文提示**。重錄該槽位**承載核心主題**、不該為簡化而拿掉。  
新手友善靠「**站光點上時 HUD 動態提示**」解決、不必動核心邏輯。

> 餘響不只是平台跳躍解謎、它在玩「**站在你過去的位置上做不同的選擇**」這件事——重錄該槽位是這個 mechanic 的精神化身。

## 三、Q 鍵刪除槽位 — 是否加滑鼠/地圖整合

### 現況
Q 鍵 + 站亮光點上才有效。要刪某個槽位、必須走到該光點位置。

### 三個改動方向

#### 方向 A：加滑鼠點擊刪除（如 shift+LMB）
- ✅ 便利
- ❌ 與既有 LMB=record / RMB=summon 衝突、需學新手勢
- ❌ **嚴重破壞儀式感**——一鍵刪除過去的我、失去重量感

#### 方向 B：地圖內整合刪除
- ✅ 便利度中
- ✅ 既有 UX 一致（地圖已是「光點全覽」介面）
- ✅ 仍有些儀式感（要走流程：開地圖 → 點光點 → 確認）
- ✅ 新手發現性高（地圖按鈕明顯）
- ⚠️ 實作成本中

#### 方向 C：保持原狀
- ❌ 便利度低
- ✅ 儀式感強——「**過去的我不能輕易抹除**」、必須親身回到那個地點
- ❌ 新手要靠 Sign / HUD 教

### 結論

**保持原狀**。理由：
1. 餘響「靜謐 / 儀式」基調、便利性是次要
2. 「過去的我有重量、不能輕易抹除」是主題核心
3. 走過去刪 = 強迫玩家面對「要刪掉的是什麼」

### 進 v2.0 backlog 觀察項目
**M16.5 外部測試**後、若玩家強烈反饋「Q 太麻煩」→ 考慮加方向 B（地圖內刪除作為**補充**、非替代）。

## 四、槽位數量：5 個 vs 3 個

### 現況
5 個槽位 + FIFO（最舊覆蓋）。HUD 顯示 5 格。

### 全面對比

| 因素 | 5 槽位（現況） | 3 槽位 |
|---|---|---|
| 設計彈性 | 高（可做順序鎖、4+ 分身合奏） | 中（最多 3 分身合作） |
| 玩家認知負擔 | 中 | 低 |
| 解謎挑戰深度 | 高 | 中 |
| HUD 簡潔度 | 中 | 高 |
| 詩意感 | 累積感 | 精煉感 |
| 錄製失敗容錯 | 高（FIFO 自動覆蓋） | 中 |
| 設計師壓力 | 較鬆 | 較緊 |

### 從謎題提案實際使用觀察

[謎題提案.md](../docs_map/謎題提案.md) 各案例：
- Room 1-4 教學：1-2 個分身
- Room 5-7（拉桿/計次/殘骸）：1-3 個
- Room 8 拉桿節奏：1 個
- Room 9C 多分身合奏 / 順序鎖：3+ 個

→ **絕大多數謎題用 1-3 個、只有最進階的需要 4-5 個**。

### 改 3 槽位的成本（純估算）

- 改 RecordingManager 槽位上限
- 改 HUD（5 格變 3 格）
- 改 LightPoint 1-5 顯示
- 改地圖介面光點顯示
- 重檢 PressCounter 跨房邏輯
- 文件更新（玩法鎖定清單、工具與機關清單）
- 估時 4-6 小時

### 結論

**保留 5 個、設計時用約束控制**。  
讓 M15 設計師選「**這關只用 1/2/3 個**」、不必所有關卡都用滿 5 個。  
進 [v2.0 backlog](玩法鎖定清單.md)：「**槽位數量檢討**」、看 M16.5 玩家是否反饋「5 個太多」。

### 槽位限制設計範例（M15 內容擴展時可用）
- 教學房：限 1 槽
- 中段房：開放 2-3 槽
- 進階房：開放 4-5 槽（包括順序鎖）

## 五、傳送門：是否從地圖直接傳送 + 按鍵調整

### 現況
- 玩家走進傳送門範圍 → 按 R → 開地圖 → 點目標 → 傳送
- R 鍵承擔 4 種行為（傳送 / 重錄 / 結束錄製 / 新錄製）
- W 是跳躍替代鍵（搭配 Space、↑）

### 設計意圖回顧
[docs_map/地圖規劃.md § 9.3](../docs_map/地圖規劃.md)：傳送門 = **死路盡頭快捷回岔路口**。  
類似《魂系列》篝火——必須親身抵達才能用。

### 三個方向對比

#### 方向 A：保持現狀（走過去 + R）
- ✅ 探索成就感強
- ❌ 操作便利低、卡關時要走回頭路

#### 方向 B：完全自由（地圖內隨點隨傳）
- ✅ 操作便利極高
- ❌ 探索感完全消失、傳送門變「快速移動的 GPS」
- ⚠️ 設計影響大——傳送門「位置選擇」變得無意義

#### 方向 C（推薦）：混合（Dark Souls 篝火模式）
- 玩家**首次必須親身抵達**啟用傳送門
- 之後可從地圖內任意點選傳送
- ✅ 探索成就感保留
- ✅ 操作便利高
- ✅ 設計原意吻合
- ✅ 學習曲線低

### 按鍵 R → W 的提案

⚠️ **W 是跳躍替代鍵**（已綁 jump action）。改成傳送 = **與跳躍衝突**：玩家在傳送門範圍按 W 想跳、結果觸發傳送 → 災難級 UX。

→ **W 是禁區、不要選**。

### 真正解法：讓傳送離開按鍵綁定、改成地圖內點選

| 動作 | 按鍵 |
|---|---|
| 開地圖 | Tab |
| 點選傳送門目標 | 滑鼠 LMB（地圖內、不影響世界內 LMB=錄製） |
| 確認傳送 | Enter / 再點一次 |
| 取消 | ESC / Tab |

**R 鍵省下「傳送」一個責任、剩 3 個行為**：

| 情境 | R 鍵動作 | 變化 |
|---|---|---|
| ~~在傳送門範圍~~ | ~~傳送~~ | **移除** |
| 站亮光點上 | 重錄該槽位 | 保留 |
| 錄製中 RecordingProxy | 結束錄製 | 保留 |
| 站地面 | 新錄製 | 保留 |

→ R 鍵語意更聚焦「**錄製操作**」、不再有「傳送」這個離題功能。

### 統合方案（推薦）

新 UX：
1. 玩家走進傳送門範圍 → 視覺提示「**已啟用**」+ HUD 提示「**Tab 開地圖傳送**」
2. 之後任何時刻、玩家按 **Tab** 開地圖
3. 地圖上看到所有**已啟用**傳送門（亮色）+ **未啟用**的（灰色）
4. 點亮色傳送門 → 確認 → fade + 瞬移
5. R 鍵不再涉及傳送

完全不必動 R 鍵綁定、不需新鍵位、Recording 系統不受影響。

### 仍須保留的限制
- 錄製中禁用（PlayerController.activate_teleporter 已有 state 檢查）
- 傳送門必須「**已造訪**」才解鎖（保留設計意圖）

### 實作成本估算（不做、只估）

| 工作 | 估時 |
|---|---|
| Teleporter 加「discovered」狀態 + signal | 1h |
| MapOverlay 內加「點擊已啟用傳送門 → 觸發傳送」邏輯 | 2h |
| MapOverlay 視覺差異（亮/灰） | 1h |
| Player.gd 移除 R 鍵的傳送邏輯 + HUD 上下文提示更新 | 0.5h |
| 測試（含 Recording 一致性、各狀態邊界）| 1.5h |
| **總計** | **6h ≈ 1 天** |

可放進 M14a（視覺接口框架）順手做、不必為它單獨開階段。

## 七、Freeze 與時程考量

[玩法鎖定清單.md](玩法鎖定清單.md) M13.5 已啟動。本文件討論的內容大部分屬於「UX 改進」而非「新增機制」、不算嚴重破 freeze、但仍應慎重處理：

| 改動類型 | freeze 評估 | 建議處理 |
|---|---|---|
| 機關種類（新增/修改）| 🔴 破 freeze | 進 v2.0 backlog |
| 玩家動作集（新增/修改） | 🟡 邊界 | 視具體改動、必要時進 M14a |
| Recording 結構 | 🟢 不影響 | 自由動 |
| HUD / UI 改進 | 🟢 不影響 | M14a 順手做 |

本文件 4 個主題分布：
- 主題 1（R 重錄）：HUD 改進 → M14a 安全
- 主題 2（Q 刪除）：UX 改動 → 邊界、暫不動
- 主題 3（5→3 槽位）：機制改動 → v2.0 backlog
- 主題 4（傳送門 UX）：UI 改動 → M14a 順手做

## 八、給未來自己的提醒

1. **不要為了便利犧牲詩意**——餘響的「靜謐 / 儀式」基調是核心、便利性是次要
2. **freeze 是紀律、不是教條**——若有強烈設計理由可破例、但要明確紀錄理由
3. **M16.5 外部測試是最終仲裁**——本文件多數「我的看法」是個人判斷、玩家實測才知道對錯
4. **W 鍵跳躍綁定是地雷**——任何「傳送 / 互動 / 攻擊」改動絕不要碰 W
