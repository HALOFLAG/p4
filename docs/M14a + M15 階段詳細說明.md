M14a — 視覺接口框架（1 週）
階段目標
只做接口、不做效果。

建立未來視覺 polish 要套用的「架構基礎」、但不在這個階段做動畫填充、shader、粒子調參。

想成「鋪電線、不裝燈」——M14a 鋪好所有插座、M14b 才買燈裝上去。

為什麼分 M14a / M14b
階段	內容	為何
M14a（現在）	接口、狀態 mapping、Light slot 系統	M15 設計關卡時可預期「狀態 X 會有動畫 Y」、不必等

該做的事 ✓
1. 狀態 → 動畫 mapping
列出所有「會有視覺反應」的狀態：

物件	狀態	對應動畫名稱
Player	idle / walk / jump / fall / record / die	idle, walk, jump, fall, ritual, die
Door	closed / opening / open / closing	closed, open, close
Lever	off → on	flip_on, flip_off
Spring	compress	compress
TriggeredPlatform	move_to_target / move_back	move, return
CrumblingPlatform	crumble / restore	crumble, restore
LightPoint	bright / trace	pulse, fade
動畫內容空也可——M14a 只負責「動畫名稱定下來」、M14b 才填內容。

2. AnimationPlayer 框架建立
每個元件加 AnimationPlayer 子節點、用統一命名規則：


Door (StaticBody2D)
├── Visual (Polygon2D)
├── Collision (CollisionShape2D)
└── AnimationPlayer        ← 加這個
    ├── open（空動畫）
    └── close（空動畫）
腳本內呼叫 $AnimationPlayer.play("open") 取代既有 _physics_process 內手動插值。

3. Light slot / layer 系統
為光照分層、之後可獨立控制：

Layer 名	用途
ambient	環境光（CanvasModulate）
mechanism	機關光（按鈕、Lever、彈簧的指示燈）
character	角色光（玩家、Clone 自帶光暈）
ritual	儀式光（LightPoint、錄製儀式）
未來想「暗室時關掉 ambient 但保留 mechanism」就只動對應 layer、不必逐個物件改。

4. 最關鍵：Recording 一致性驗證
換 AnimationPlayer 後、第一次必須驗證 Recording 還能 deterministic：

設 AnimationPlayer.callback_mode_process = ANIMATION_PROCESS_PHYSICS（與 _physics_process 同步）
跑「錄一段含機關互動 → 重現 3 次 → 比對軌跡」
通過才能繼續、不通過必須回退到 _physics_process 手刻
5. 順手做（從 備忘1）
傳送門 UX 改成混合方案：首次抵達啟用、之後可從地圖內遠傳（~6h）
R 鍵 HUD 上下文提示：站光點上時顯「R=重錄此槽位」（~1h）
