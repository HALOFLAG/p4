# 文案用語規劃 — 餘響 / Lingering Echo

> 本文整理遊戲所有玩家可見文字的命名策略、設計理由、與替換清單。
>
> 起因：試玩回饋指出「召喚」「槽位」等術語讓玩家困惑、無法理解錄製/重現機制。
>
> 結論：採「**動作描述為主、極簡詩意短詞為輔**」（風格 B 混搭）。

---

## 一、起源：試玩回饋

2026-05-03 的試玩回饋核心引述：

> 「我只知道按 R / 誰知道要按 R 開始記錄、按 12345 重播 / 基礎操作不要讓玩家猜」
>
> 「我當初看不懂甚麼**召喚** / 我覺得用『**重現**』好一點 / 應該說按R開始記錄過去軌跡 > 再次按R結束紀錄 > 按1重現軌跡」

兩個重點：
1. **基礎操作沒被教會**（HUD 文字提示沒生效、玩家直接無視）
2. **「召喚」一詞誤導**（試玩者聯想到 JRPG 召喚怪物、與時空主題違和）

## 三、設計討論：命名 vs 動作描述

### 三種風格對比

#### 風格 A — 純動作描述（最極端、不推）
不命名任何機制。所有提示用「按 X → 看到 Y → 然後 Z」。

| 位置 | 文字範例 |
|---|---|
| HUD | `R 開始/結束記下你的動作　1~5 讓剛才的你再走一次` |
| Sign Room 3 | `按 R → 走到按鈕站著 → 按 R 結束 → 按 1 看剛才的你重做一遍` |
| EndingScreen 統計 | `你讓自己再走過：12 次／你倒下又起來：3 次／你留下：8 段過去` |

優點：零專有名詞、最自由想像  
缺點：統計列冗長、玩家口頭討論時還是會自己取名

#### 風格 B — 混搭（**推薦**）
- **教學/Sign**：用動作描述
- **統計/標籤**：用最短的詩意短詞

| 位置 | 文字範例 |
|---|---|
| HUD | `R 開始/結束記下動作　1~5 讓過去的你再走一次　光點上：R 重做 · Q 抹去` |
| Sign Room 1（新） | `按 R → 走幾步 → 再按 R → 按 1 看看會發生什麼` |
| Sign Room 3 | `按 R → 走到按鈕站著 → 按 R → 按 1` |
| Sign Room 4 | `你需要兩個過去的自己同時按住兩邊` |
| ContextHint | `第 N 段過去的起點 — R 重做 / Q 抹去` |
| EndingScreen 統計 | `重現：12 次／留下：8 段／餘骸：2 個` |

優點：教學動作為先、統計仍簡潔、保留「終響/餘骸/重現/段」等少量詩意短詞  
缺點：仍有少量名詞（但**自洽詩意短詞、不是 JRPG 用語**）

#### 風格 C — 傳統命名
為機制定義術語、全文件統一使用。

| 位置 | 文字範例 |
|---|---|
| HUD | `R 記錄/結束軌跡　1~5 重現對應軌跡　光點上：R 重錄 · Q 刪除` |
| EndingScreen 統計 | `重現軌跡：12 次／留下軌跡：8 次／餘骸：2 個` |

優點：詞彙統一、好溝通  
缺點：仍是在「教詞彙」、部分玩家覺得需記新術語

### 為什麼選風格 B

| 條件 | A 純動作 | **B 混搭** | C 命名 |
|---|:---:|:---:|:---:|
| 解決試玩「不知道怎麼玩」 | ★★★★ | **★★★★★** | ★★ |
| 統計畫面簡潔 | ★ | **★★★★★** | ★★★★★ |
| 與「餘響」詩意基調契合 | ★★★★★ | **★★★★** | ★★★ |
| 玩家可口頭交流 | ★★ | **★★★★** | ★★★★★ |
| 製作者實作成本 | ★★★★（要寫長句） | **★★★★** | ★★★★★ |

### 風格 B 的核心原則

1. **教學區（Sign / HUD）以動詞 + 鍵位為主**
   - 「按 R 開始記錄」、不說「啟動錄製模式」
   - 「按 1 讓過去的你再走一次」、不說「召喚槽位 1 的分身」

2. **統計區用最短詩意短詞、不超過 2 字**
   - 「重現」「留下」「餘骸」「段」「次」「個」
   - 都是有意義感的常用字、不需要學習

3. **不為任何系統取「正式名字」**
   - 沒有「召喚系統」「軌跡系統」「重現法術」這類 system-level 命名
   - 機制的存在感由動作 + 視覺定義、不由名字定義

4. **「過去的你」是核心短語**
   - 跨 Sign / HUD / Stat 重複出現
   - 自然好懂、貼合時間 / 回響主題
   - 取代「分身」（雖然「分身」作為名詞仍可少量保留）

## 七、配套設計要求

採用「動作描述」風格的隱含要求：

### 7.1 視覺回饋必須夠強
沒有名詞解釋的時候、必須靠視覺與動作講話：
- ✓ C1 雙影分裂回合（按 R 時雙影展開合併）— 已實作
- ✓ Letterbox 黑邊 + 紅邊（cinematic、明確「進入特殊模式」）— 已實作
- ✓ 光點生成（記錄結束、亮起）— 已實作
- ⚠ 可加：proxy 顯形時「啵」一下的環狀漣漪（強化「分裂感」）

### 7.2 Room 1 必須是強制教學
Sign 寫著「按 R → 走幾步 → 再按 R → 按 1」是不夠的、要**做不出來就過不去**：

建議設計：
- Room 1 結尾放一道矮門
- 矮門只在玩家**完成過一次完整流程**（按 R → 結束錄製 → 召喚某個槽位）後開啟
- 玩家不練習就卡在 Room 1
- 對應 PressCounter 但 target = 1、track 範圍只看「召喚事件」

### 7.3 預期玩家會自己取名
試玩者口語可能稱呼為：「鬼」「影子」「過去的我」「分身」⋯⋯
- 不要糾正
- 如果某個叫法明顯佔多數、未來再考慮正式化
- 短期內保持文字「中性 + 動作描述」

## 八、後續驗證

下一輪試玩時觀察：
1. 玩家進 Room 1 → 不看 HUD 也能 30 秒內完成 R → R → 1 三步驟
2. 玩家不會問「這要怎麼玩」
3. 玩家在 Room 3 看到 Sign（4 個鍵位提示）就能解出謎題
4. 玩家口頭如何稱呼「按 1 出現的東西」、收集自然命名
5. 通關後讀統計、能否一眼看懂「重現 12 次 / 留下 8 段 / 餘骸 2 個」是什麼意思

如有 80%+ 玩家在 Room 1 自己學會、即可確認此設計成功。

## 附錄：未採用的方案

### 為什麼不選風格 A（純動作）
- 統計畫面 6 行各 8-12 字、太冗長、不像 stats UI
- 「你倒下又起來：3 次」讀起來怪、不如「死亡：3 次」直接
- 統計區用詩意短詞已能達到「不像術語」效果、不必極端

### 為什麼不選風格 C（命名）
- 試玩者明確抗拒「召喚」、改名「重現」也只是換個術語
- 「軌跡系統」「重現槽位」聽起來仍像 RPG UI、沒解決根本問題
- 教學負擔仍在玩家身上

### 為什麼不取消「光點」這個詞
- 「光點」是**描述性**的（你看到一個發光的點）、不是術語
- 玩家視覺上認得這個東西、口語自然會說「那個亮亮的」
- 用「光點」二字標籤化是合理的、不違反風格 B 原則
